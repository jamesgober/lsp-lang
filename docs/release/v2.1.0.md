# lsp-lang v2.1.0

The server had no limit on how many documents a client could open. Each
`didOpen` could bring a large text plus its syntax tree, and nothing capped how
many stayed open, so a client that kept opening documents could make the server
hold any amount of memory. An editor on the same machine is trusted, but a
shared or remote language server is not, so this release caps it.

## Added

- **`Server::with_document_limit(documents, bytes)`** sets the most documents
  held open at once and the most bytes of text between them. The defaults are
  4096 documents and 512 MiB.
  - A `didOpen` past either cap is refused with a `window/logMessage`, and the
    document stays closed.
  - A `didChange` that would grow the text past the byte cap is refused the
    same way. The document is kept at its last version, out of step, until the
    client sends its whole text again, which is how any change that cannot be
    applied is already handled.
  - Closing a document frees its room.

## Changed

- The default message limit is now 64 MiB, down from 256 MiB. That is still far
  above any source file an editor sends, and `with_message_limit` raises it.

## Upgrading

No code changes are needed. A server that expects clients to open more than
4096 documents, or more than 512 MiB of text, should raise the cap with
`with_document_limit`.

```toml
[dependencies]
lsp-lang = "2.1"
```
